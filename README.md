# PETWASH

폐페트병 세척 공정 지능화 관리 시스템.

"지능형공정데이터관리" 팀 프로젝트 프로토타입.
수거된 병을 카메라로 하나씩 오염/비오염으로 선별해 따로 모으고, 모인 병을 세척 배치로 묶어 각자에 맞는 조건(약품 농도·온도·시간)으로 세척하는 웹 관리 시스템이다.
세척수 센서 값을 보고 추천 조치를 내고, 작업자가 승인하면 장치에 목표값을 보낸다.
오염 병과 깨끗한 병이 같은 조건으로 씻기지 않게 해서, 깨끗한 병은 세척 자원을 덜 쓰고 더러운 병은 충분히 씻어 플레이크 품질 편차를 줄이는 것이 목표다.

```
[장치/시뮬레이터] --MQTT--> [Mosquitto] --MQTT--> [FastAPI 서버] --WebSocket--> [웹 브라우저]
   센서·카메라·상태                                  │  ├─ InfluxDB 3 (센서 값, 카메라 판정)
   ← 목표값·배치 명령                                │  └─ SQLite (수거·세척 배치, 저장함, 목표값·결정 이력, 요약)
```

### 배치 흐름

```
수거 배치(L…) ─ 카메라 선별 ─▶ 오염 저장함   ─ 임계치 도달 ─▶ 세척 배치(W…, 오염 레시피)   ─▶ 세척조
                            └▶ 비오염 저장함 ─ 임계치 도달 ─▶ 세척 배치(W…, 비오염 레시피) ─▶ 세척조
```

- **수거 배치** (L20261119-001): 수거된 순서대로 만든 단위. 카메라 선별까지만 쓴다.
- **선별 저장함**: 카메라 뒤 선별 게이트가 판정 결과대로 병을 오염/비오염 저장함으로 보낸다.
- **세척 배치** (W20261119-001): 저장함에 병이 임계치만큼 모이면 자동으로 묶인다. 세척 조건, 목표값, 결정 이력, 요약은 모두 세척 배치 단위다.
  어느 수거 배치의 병이 몇 개 들어갔는지 기록하므로 세척 배치에서 수거 배치까지 거슬러 올라갈 수 있다.
- 선별(카메라)과 세척(세척조)은 다른 설비라서 동시에 진행할 수 있다. 수거 배치 선별 1개, 세척 배치 세척 1개까지.

## 1. 준비물 (Windows 11 기준)

| 항목 | 확인 방법 |
|---|---|
| Python 3.10 이상 | `python --version` |
| Mosquitto (localhost:1883, 익명 접속) | `Get-Service mosquitto` → Running |
| InfluxDB 3 Core (http://localhost:8181) | 실행 중이어야 하고 관리자 토큰이 필요 |

InfluxDB 토큰이 없으면 InfluxDB 폴더에서 한 번만 만든다. 출력된 토큰은 다시 볼 수 없으니 바로 `.env`에 저장한다.

```powershell
.\influxdb3.exe create token --admin
```

`petwash` 데이터베이스는 첫 데이터가 들어올 때 자동으로 만들어진다.

터미널 두 개를 열고 각각 PET 폴더에서 실행한다.

**터미널 1: 서버**

```powershell
.\.venv\Scripts\python.exe -m uvicorn server.main:app --port 8000
```

**터미널 2: 장치 시뮬레이터**


## 4. 시연 순서

화면은 옛날 PC 바이오스 설정 화면 느낌(파란 제목 줄, 회색 메뉴, 이중선 상자)을 흰 바탕에 살렸다. 바이오스처럼 숫자키 1~5로 화면을 이동할 수 있다.
글꼴은 jsDelivr에서 받는 한글 픽셀 글꼴 Galmuri(SIL OFL)이고, 인터넷이 없으면 윈도우 기본 돋움체로 대신 표시된다.

0. **시연용 가속**: 실제 공정은 세척에 10~20분이 걸리므로, 발표·테스트 때는 대시보드 위쪽의 "(테스트) 10배 가속"을 누른다.
   시뮬레이터 안의 시간(가열, 약품 소모, 탁도, 세척 타이머, 카메라 판정)이 10배 빠르게 흘러 세척 20분이 약 2분에 끝나고, 수거 배치 1개(병 100개) 선별이 약 3초에 끝난다.
   가속 중에는 메뉴 줄에 "x10 가속 중 (테스트)"가 표시되고, 남은 시간 옆에 실제로 걸리는 시간이 함께 나온다.
   시뮬레이터를 다시 켜면 항상 실제 시간(1배)으로 시작한다.
1. **대시보드**: 그래프가 실시간으로 갱신되는지 본다 (실제 시간 2초마다, 10배 가속 중에는 0.2초마다). 위쪽 카드에 선별 중 수거 배치, 저장함, 세척 중 배치가 나온다.
   시뮬레이터를 끄면 15초 뒤 "장치 연결 끊김" 경고가 뜬다.
2. **배치 관리 → 수거 배치 목록**: 메모를 입력하고 "새 수거 배치 만들기" → "선별 시작".
   시뮬레이터가 병 100개를 판정해 오염/비오염 저장함으로 보내고, 다 판정하면 수거 배치가 자동으로 "선별 완료"가 된다.
3. **배치 관리 → 선별 저장함**: 수거 배치를 몇 개 더 선별하면 저장함이 차오른다. 임계치(기본 100병)에 도달하는 순간 그 저장함이 세척 배치로 묶여 "세척 배치 목록"에 "대기"로 생긴다.
   작업 마감 때처럼 임계치 전에 묶고 싶으면 "지금 묶기"(두 번 눌러 확인).
4. **배치 관리 → 세척 배치 목록**: 대기 중인 세척 배치에서 "세척 시작"을 누르면 장치가 그 배치를 세척조에 넣는다.
   세척하는 동안에도 다른 수거 배치를 선별할 수 있다.
5. **세척 제어**: 세척 배치의 레시피(오염/비오염)로 추천 조치와 근거가 나온다. "추천 승인"을 누르면 레시피 목표값이 장치로 간다.
   "장치 적용 여부"가 "적용됨"으로 바뀌고, 대시보드 그래프에 목표 점선이 생긴다.
   값을 바꾸고 싶으면 슬라이더(안전 한계 범위)로 조절해 "이 값으로 전송 (수동)".
6. 비오염 세척 배치인데 약품이 기대보다 빨리 소모되면 몇 분 뒤 "선별 오류 의심, 오염 레시피로 변경 검토"가 뜬다 (오염 병이 비오염 저장함으로 잘못 간 경우).
   배치 관리의 "세척 중 배치"에서 레시피를 오염으로 바꾸고 다시 추천 승인하면 된다. 레시피 변경은 결정 이력에 남는다.
7. 탁도가 기준을 넘으면 "세척수 교체 권장"이 뜨고, "세척수 교체 지시"로 새 물로 바꿀 수 있다.
8. **배치 관리**에서 "세척 배치 종료" → **이력**에서 출처 수거 배치, 평균 농도·온도, 약품 투입 시간 등 요약 확인 → "CSV 내보내기"(엑셀에서 바로 열림).
9. **설정**에서 레시피, 저장함 임계치, 경고 기준을 바꾸고 저장하면 바로 반영된다. 임계치를 지금 저장함 병 수보다 낮추면 그 자리에서 세척 배치로 묶인다.

## 6. MQTT 토픽 (JSON, 시간은 ISO8601)

| 토픽 | 방향 | 내용 |
|---|---|---|
| `petwash/sensor/wash` | 장치→서버, 2초 | concentration_pct, temp_c, turbidity_ntu, level_pct, pump_on, heater_on |
| `petwash/camera/result` | 장치→서버, 병마다 | batch_id(**수거 배치** 번호), label(contaminated/clean), confidence |
| `petwash/control/setpoint` | 서버→장치 | batch_id(**세척 배치** 번호), target_concentration_pct, target_temp_c, wash_time_min, issued_by, issued_at |
| `petwash/device/status` | 장치→서버, 5초 (하트비트) | state, message, batch_id(세척조의 세척 배치), applied(적용 중 목표값), last_command(마지막 명령 적용/거부), remaining_s, lot_id·lot_remaining(선별 중 수거 배치와 남은 병 수), bins(저장함 병 수) |
| `petwash/control/batch` | 서버→장치 (**추가**) | batch_id, action (아래 표) |
| `petwash/control/sim` | 서버→시뮬레이터 (**추가, 시연용**) | speed: 1 또는 10 |

원래 명세의 토픽과 필드 이름은 그대로 두었다. `batch_id`는 토픽에 따라 뜻이 다르지만 번호 앞 글자로 구분된다 (L = 수거 배치, W = 세척 배치).

`petwash/control/batch`의 action:

| action | batch_id | 장치가 하는 일 |
|---|---|---|
| `sort_start` | 수거 배치 | 카메라 판정 시작. 병마다 선별 게이트로 저장함에 보냄. 다 판정하면 상태를 바로 보내 서버가 "선별 완료"로 바꿈 |
| `sort_stop` | 수거 배치 | 판정 중단 (작업자가 선별을 수동 종료할 때) |
| `bundle` | 세척 배치 | 찬 저장함을 이 세척 배치로 표시해 빼 두고 빈 저장함으로 교체 (stream, count 포함) |
| `wash_start` | 세척 배치 | 그 배치를 세척조에 넣고 목표값을 기다림 (stream, count 포함) |
| `stop` | 세척 배치 | 세척 종료: 펌프·히터 정지 |
| `replace_water` | 세척 배치 | 세척수 교체 |

`petwash/control/sim`은 시연용 가속 전용이다. 시뮬레이터만 구독하고 실제 장치는 무시한다.
시뮬레이터는 센서 값과 상태에 `time_scale`(배속)을 함께 보낸다. 서버는 이 값으로 농도 감소 속도를 "장치 시간 기준 %p/분"으로 환산하므로, 배속과 상관없이 같은 추천이 나온다.
가속 중에도 제어는 장치 시간 2초 간격으로 한 단계씩 진행되므로 온도·농도 제어 결과는 실제 시간일 때와 같다.

## 7. 데이터 저장

- **InfluxDB (`petwash`)**: `wash_sensor`(센서 값), `camera_result`(병 판정, batch_id 태그 = 수거 배치)
- **SQLite (`data/petwash.db`)**
  - `lots`: 수거 배치, 오염/비오염 판정 수
  - `bin_contents`: 저장함에 지금 들어 있는 병 (수거 배치별 개수)
  - `wash_batches`: 세척 배치 (구분, 레시피, 병 수, 묶은 방식, 상태)
  - `wash_batch_sources`: 세척 배치 ← 수거 배치 추적 (몇 병씩 왔는지)
  - `setpoints`: 보낸 목표값과 장치 적용/거부 결과
  - `decisions`: 추천에 대한 작업자 결정(추천 승인 / 수동 수정 / 세척수 교체 지시 / 레시피 변경)
  - `batch_summaries`: 세척 배치 종료 시 요약. InfluxDB 3 Core는 긴 기간 조회에 제약이 있어서 따로 저장한다.

처음부터 다시 시작하려면 서버를 끄고 `data\petwash.db`를 지운다.
이전 구조(수거 배치 하나로 세척까지 관리하던 버전)의 DB가 있으면, 서버가 시작할 때 지우지 않고 `data\petwash.v1-backup-날짜.db`로 옮긴 뒤 새로 만든다.

## 8. 라즈베리파이로 옮길 때

`device/sensors.py`의 인터페이스를 실제 하드웨어 클래스로 구현하고, `simulator.py`에서 `SimulatedWashTank`·`SimulatedCamera`·`SimulatedSorter` 대신 그 클래스를 쓰면 된다. 통신과 로컬 제어 코드는 그대로 쓸 수 있다.

- `SensorReader.read()`: 전도도 센서 + ADS1115(농도), DS18B20(온도), HX711 로드셀(수위), 탁도 센서
- `Actuators.set_pump()` / `set_heater()`: GPIO 릴레이
- `CameraReader.classify()`: Intel RealSense + 분류 모델
- `Sorter.route()`: 카메라 뒤 선별 게이트 (솔레노이드 밸브 + 에어 노즐 또는 서보 플랩) → 오염/비오염 저장함

서버나 네트워크가 끊겨도 장치는 마지막 목표값과 안전 한계 안에서 계속 제어한다. 다만 지금은 목표값을 메모리에만 들고 있어서, 장치가 재부팅되면 목표값이 사라진다.

## 9. 알려진 한계

- **안전 한계 이중 관리**: `config/recipes.yaml`과 `device/controller.py` 두 곳에 같은 값이 있다. 웹 설정 화면에서는 바꿀 수 없고, 바꿀 때는 두 곳을 함께 수정해야 한다.
- **세척조 1개, 세척수 공유**: 오염 배치를 씻은 물에 비오염 배치를 바로 넣으면 농도·탁도가 높은 상태로 시작한다. 필요하면 배치 사이에 "세척수 교체 지시"를 한다.
- **저장함은 통째로 묶음**: 세척 배치는 저장함에 있는 병을 전부 묶는다. 일부만 꺼내 묶는 기능은 없다.
- **농도 감소 속도**: 서버 메모리에서 최근 10분 데이터로 계산하므로, 서버를 재시작하면 2분 정도 "판단 보류"가 된다.
- **가동 시간 근사**: 약품 투입·히터 가동 시간은 "켜져 있던 측정 수 × 2초"로 계산한 근사값이다.
- **시뮬레이터 재시작**: 시뮬레이터를 다시 켜면 진행 중이던 세척 상태와 저장함 안의 병(숨겨진 실제 오염 여부)이 사라진다.
  서버의 배치·저장함 기록은 그대로 남는다. 이때 세척 배치를 시작하면 시뮬레이터는 저장함 구분에 따른 기본 오염 비율(오염 85%, 비오염 10%)을 쓴다.
- **10배 가속 중 데이터 양**: 센서 값이 초당 5건씩 쌓인다. 10분 가속하면 InfluxDB에 약 3,000건이 쌓이는데, 시연 용도로는 문제없는 양이다.
- **보안**: 로그인·권한 기능이 없다. 수업용 로컬 프로토타입 전제다.
